# FASTA — `scripts/fastazl`

Byte-exact FASTA compression. One shipped model, no training on your data.

## Use

```bash
# compress (archetype-free: one model handles every FASTA)
scripts/fastazl compress genome.fna genome.fazl

# compress and prove the round trip in the same run
scripts/fastazl compress genome.fna genome.fazl --verify

# decompress
scripts/fastazl decompress genome.fazl restored.fna

# what is in an archive
scripts/fastazl info genome.fazl
```

Options: `--threads N` (default: all cores), `--verify` (compress-only; decodes
the archive and `cmp`s it against the input).

Environment overrides: `FASTA_MODEL` (path to the `.zlc`), `ZLI`, `FASTA_PRE`,
`FASTA_POST`.

## What is preserved

The transform (`FAV5`) is fully reversible. Verified on a corpus of edge cases
and real genomes:

- **soft-masking** — lower-case repeat regions round-trip exactly
- **IUPAC ambiguity codes** — `N`, `R`, `Y`, `W`, … stored as run-length exception runs
- **line width** — any wrapping (60, 70, 80, ragged, or one long line) is reproduced
- **CRLF** — `\r` is an exception byte, not stripped
- **trailing newline** — a file that does not end in `\n` stays that way
- **header text** — kept verbatim, byte for byte

There is no "sequence-only" or "case-insensitive" mode. If `cmp` is not silent,
that is a bug.

## How it works

```text
genome.fna ─► biocompress_preprocessor (FAV5) ─► chunks ─► zli compress ─► genome.fazl
                                                                              │
restored.fna ◄─ fasta_postprocess ◄─ chunks ◄─ zli decompress ◄────────────────┘
```

FAV5 splits a record-aligned chunk into:

| stream | content |
|---|---|
| `packed2bit` | ACGT at 2 bits/base |
| `case_runs` | run lengths of upper/lower over base positions |
| `exc_gaps` / `exc_lens` / `exc_bytes` | run-length exceptions (N, IUPAC, `\r`, …) |
| `line_lens` | bytes per sequence line |
| `hdr_lens` / `rec_nlines` / `headers` | record headers and layout |
| `preamble` | anything before the first `>` |

`schemas/fasta_packed_v5.sddl` describes this layout so OpenZL can compress each
stream with its own codec instead of treating the container as one opaque blob.

**Chunking.** The input is cut on record boundaries (targeting ≤450 MiB), so a
single chromosome larger than that becomes one chunk. Chunks compress in
parallel and decode independently.

**Fallback.** Any chunk the trained model cannot compress is retried with
`zli compress --profile serial`. `fastazl info` reports `fallback_parts`. The
round trip is byte-exact either way — only the ratio differs.

## Where it does well, and where it does not

Measured against `gzip -9`, `pigz -9`, `zstd -19 --long=27`, `7z -mx=9`,
`xz -9e --block-size=192MiB` (see `results/benchmark_fasta_*.csv`):

- **Mammalian genomes** (human T2T / GRCh38, mouse GRCm39): our method wins.
- **Highly repetitive plant genomes** (bread wheat, ~85 % repeat content):
  `xz` and `7z` win. Their large LZ windows exploit long-range repeats that a
  2-bit pack plus per-stream entropy coding does not. This is a real limitation,
  not a tuning artifact.

Numbers are regenerated by `sbatch batch_files/benchmark_fasta.slurm`.

## Regenerating the model (maintainers)

Not needed to use the tool. Only if OpenZL is upgraded:

```bash
bash scripts/train_fasta_model.sh              # -> artifacts/fasta_model.zlc
cat artifacts/fasta_model.profile              # which OpenZL profile won
```

It trains one model over a fixed multi-species corpus (E. coli, yeast,
*A. thaliana*, human, mouse, wheat), tries several OpenZL profiles
(`sddl`, `lz`, `serial`), and keeps whichever compresses the validation chunks
smallest while still round-tripping byte-exact.
